# Contributing

This project is small and personal, but contributions are welcome when they raise the bar.

## What we are looking for

Corrections to articles, tutorials, or code samples. Small focused improvements (a fixed typo, a clearer paragraph, a working code path) are easy yeses.

New articles, tutorials, or workflows that fit one of the topic clusters in `SEO.md`. Pitch first via an issue describing the angle and target reader.

Improvements to existing snippets and templates: better error handling, clearer naming, tests, useful comments.

## What we will probably decline

Low-effort listicles or surface-level overviews.

Promotional content, even subtly disguised. If you have a product, that is fine, but pieces that read as marketing for it are not a fit.

Articles that depend on undocumented behavior or unreleased features.

Pull requests that touch many unrelated files at once.

## Standards

Write for a working developer. Assume they know how to read code but are short on time. Lead with the answer, then explain.

Code samples must run as written. Where dependencies are required, list exact versions in the article and pin them in the example.

Use clear, plain English. Avoid hype, avoid filler, avoid "leverage" and "unlock."

Cite sources when claiming a benchmark or a behavior. Link to the official docs or a reproducible test.

## Style notes

Headings are sentence case. Code blocks specify the language. Inline code is used for filenames, commands, function names, and short identifiers. Lists are used sparingly; prefer paragraphs unless a list genuinely improves clarity.

## Filing an issue

When something is wrong, include the page or file path, what you expected, what you saw, and (if applicable) the exact reproduction steps.

## Code of conduct

Be kind, be specific, and assume good faith. Disagreements about technical decisions are fine; making them personal is not. Maintainers will close discussions that drift into harassment.

## License of contributions

By submitting a contribution, you agree that it can be released under the project's licenses: MIT for code, CC BY 4.0 for written content.
