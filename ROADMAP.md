# Roadmap

This roadmap describes where the project is heading. It is intentionally lightweight: priorities are reviewed regularly and shaped by what readers and users actually find useful.

## Guiding principles

The project compounds. Every commit should leave the repository slightly more useful than it was before. We prefer many small, high-quality additions over rare, large ones. Content and code that age well are favored over hype-driven topics.

## Phase 0 - Foundation (current)

Establish the public identity of the project: README, license, strategy documents, contribution guidelines, and a clean directory layout. Ship the first article and the first reusable workflow so the structure is not theoretical.

Deliverables: repository scaffold, MIT/CC BY license, ROADMAP, MONETIZATION, SEO, GROWTH, IDEAS, CONTRIBUTING, a first article on a topic with proven search interest, a first reusable snippet, and a first workflow.

## Phase 1 - Content baseline

Reach roughly twelve high-quality, well-structured articles and tutorials covering distinct AI-engineering topics. Cover prompt engineering, agent design patterns, retrieval-augmented generation, evals, structured output, tool use, browser automation, and rate-limit/cost handling. Each piece is self-contained, runs end-to-end on a developer laptop, and links to relevant snippets and workflows.

## Phase 2 - Distribution and SEO

Index the site on search engines, build internal linking, and submit the first articles to relevant communities (Hacker News, dev.to, r/MachineLearning, r/LocalLLaMA, r/LLMDevs, Reddit dev-tool communities, Lobsters, Indie Hackers). Add Open Graph and structured data. Track which pages drive traffic and double down on those topic clusters.

## Phase 3 - Tools and templates

Introduce two or three small, focused utilities that solve a real pain point for AI developers (for example: a token-aware text splitter, a prompt-eval harness, a streaming response logger, or a tiny CLI for managing prompt versions). Each tool ships with documentation, examples, and a clear README so it can stand on its own as a portfolio piece.

## Phase 4 - Newsletter and audience

Launch a low-frequency newsletter (monthly, then biweekly) that curates the best new content from this repository and from the broader ecosystem. Build a landing page; collect signups. The newsletter is the first asset that creates a direct relationship with readers, which unlocks every later monetization path.

## Phase 5 - Monetization experiments

Once there is consistent traffic and a small audience, test the lowest-friction monetization paths first: relevant affiliate links inside content where they genuinely help the reader, sponsored slots on the newsletter, and a single paid digital product (a deep-dive PDF or a video course module). See `MONETIZATION.md` for details.

## Phase 6 - Micro-SaaS spin-offs

Identify the one or two tools that have proven demand through GitHub stars, issues, and traffic, and spin them out into hosted versions with a free tier and a paid tier. Keep the open-source core. The repository remains the marketing hub.
